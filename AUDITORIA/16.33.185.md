# AUDITORÍA TÉCNICA V16.33.185

## 1. HALLAZGO CORREGIDO
La secuencia TDJ tenía dos fuentes distintas para el valor del título: el valor nominal/disponible y un valor ajustado por prioridad. `tdj-core-16.33.143.js` sobrescribía el valor del pago TDJ con el valor ajustado. Esto contaminaba la trazabilidad aunque el detalle económico del motor conservara otra aplicación.

## 2. EVIDENCIA DEL DEFECTO
En el caso reportado:
- TDJ de $20.000.000: resumen de secuencia mostraba $16.048.000 aplicados.
- Detalle del motor mostraba $15.548.000 aplicados.
- La diferencia de $500.000 demostraba que el resumen no estaba usando la misma fuente de verdad que el motor.
- El TDJ de $10.000.000 terminaba siendo presentado como aplicado en la obligación 1, en lugar de conservarse para la obligación 2.

## 3. CORRECCIÓN
`js/tdj-core-16.33.185.js` carga el core histórico y reemplaza exclusivamente la instrucción que sustituía `pagoActual.valor` por `pagoAjustado.valor`.

El ajuste de prioridad se conserva únicamente como metadata (`__tdjAjustePrioridad`). La aplicación económica permanece bajo responsabilidad del motor histórico.

## 4. GUARDIAS CONSERVADAS
- `tdj-secuencia-guard-16.33.183.js`: cierre cronológico y arrastre del nominal de títulos excluidos.
- `tdj-secuencia-guard-16.33.184.js`: detalle explícito de aplicación cero para TDJ excluido, evitando reutilización de otro detalle.
- `prioridad-tdj-v132.js`: prioridad de pagos posteriores y secuencia cronológica.

## 5. RESULTADO MATEMÁTICO ESPERADO
- TDJ 500.000 → 500.000 aplicado.
- TDJ 500.000 → 500.000 aplicado.
- TDJ 20.000.000 → 15.548.000 aplicado + 4.452.000 excedente.
- Pago normal posterior 8.193.000 → permanece en la obligación 1.
- TDJ 10.000.000 → 0 aplicado en obligación 1 + 10.000.000 disponibles para obligación 2.
- Obligación 2 → recibe el remanente de $4.452.000 más el TDJ íntegro de $10.000.000, además de sus pagos normales.
