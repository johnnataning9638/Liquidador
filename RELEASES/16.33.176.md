# RELEASE 16.33.176 — RECONCILIACIÓN TDJ / ENDOSO

## Problema corregido
En el escenario de una obligación con cuatro TDJ de la misma fecha, el TDJ4 de $10.000.000 podía aparecer en la trazabilidad como aplicado por $10.000.000, mientras que el detalle/PDF mostraba que realmente no se había consumido en esa obligación.

## Corrección
- Se agregó `js/tdj-secuencia-guard-16.33.176.js`.
- La guardia simula el mismo motor con el TDJ actual en $0.
- Si los pagos normales posteriores quedan completamente aplicados y la obligación queda cerrada dentro de la tolerancia operativa de $1.000, el TDJ actual no se consume.
- El valor completo queda disponible para la siguiente obligación/endoso.
- Las capas de secuencia se cargan estáticamente desde `tdj.js` para eliminar la condición de carrera de módulos que podía producir divergencia entre trazabilidad y PDF.

## Resultado esperado del caso de referencia
- TDJ1 $500.000 → aplicado $500.000 / endoso $0.
- TDJ2 $500.000 → aplicado $500.000 / endoso $0.
- TDJ3 $20.000.000 → aplicado $15.548.000 / endoso $4.452.000.
- TDJ4 $10.000.000 → aplicado $0 / endoso $10.000.000.
- Total aplicado: $16.548.000.
- Total endoso: $14.452.000.

## Protección
- No se modifican `motor-liquidacion.js`, `motor-liquidacion-oficial.js`, `motor-liquidacion-base.js` ni `tdj-core-16.33.143.js`.
- Se mantiene la lógica matemática histórica del motor.
- Se agregó `tests/regresion-tdj-176.mjs` y se incorporó a `audit-estabilidad.yml`.

Versión objetivo: **16.33.176**.
